## 零、一句话总结（最重要的一条）

> **决策提示只跟 `decisionOffer`。服务器给 offer 就亮，不给就灭。**
> **不许用任何别的字段、别的信号去"推断"决策是不是结束了。**

前面所有的错误，全是违反这一条导致的。

## 一、真实数据结构（2026-10-21 实测，别靠记忆）

### `pp/table/<桌名>` 的 player 字段

实测 300 帧，某个座位的手里出现过的字段只有这些：

```json
"7_h0": {
  "score": "9/19",
  "cards": ["A", "8"],
  "bet": "25",
  "cashOut": 705.0,
  "canDecide": true
}
```

**仅有** `score` / `cards` / `bet` / `cashOut` / `canDecide`。

**没有的字段（实测 300 帧里 0 次）**：

| 字段 | 实测出现次数 | 说明 |
|---|---|---|
| `decisionTimer` | **0** | 早期版本拿它判断"还在决策"，条件永不成立 |
| `currentDecision` | **0** | 早期版本拿它判断"已提交"，被它坑了两次 |
| `activeHand` | 极少且值多为 `None` | 早期版本拿它判断"结束"，条件永不成立 |

> ⚠️ `canDecide` **不是服务器原始字段**，是 `PPBJ.py` 自己加工出来、发给网页的。
> 原始只有 `decisionOffer`。

### 一个真实帧长什么样（Blackjack 1，MickyCabrera 坐 1 号和 7 号）

```
7_h0  canDecide=true, cashOut=705.0    ← 7 号轮到决策
1_h0  只有 score/cards/bet             ← 1 号没轮到，连字段都不带
```

**关键观察**：同一帧里**可以同时有多个座位 `canDecide`**（抓包见过 7/6/5 三个一起）。
所以"PP 是严格逐个轮流、一次只能亮一个"这个结论是**错的**。

## 二、踩过的坑（按时间顺序，全是真事）

### 坑 1：以为"网络端"是 AutoBot 的终端面板

- **做了什么**：跑去改 `AutoBot/main.py` 的 `render()`、`schedule_decision`、`acted` 去重
- **错在哪**：用户说的"网络端"是 `PP主程序/pp_receiver_vps.py`（网页看板），
  跟 AutoBot 的终端面板是**两套完全独立**的程序
- **现象**：改了半天空转，用户问"你为什么碰我这边的代码"
- **教训**：**听到"网络端 / 网页端 / 输入用户名显示决策" → 就是 `PP主程序/`。**
  先确认改的是哪个文件，再动手

### 坑 2：只认 `cashOut` 作为 EV 触发条件

- **做了什么**：网页端 `if (h.cashOut === undefined) continue`
- **错在哪**：没有兑现报价的时候（`decisionOffer` 带但没 `cashOut`）这一手就永远不算 EV
- **现象**："只有 CashOut 的时候才有决策提示"
- **修正**：触发条件加入 `canDecide`
- **教训**：`cashOut` 只是**兑现价参数**，不是"能不能决策"的开关

### 坑 3：250ms 去抖吞帧

- **做了什么**：`pp/table` 同主题消息有 250ms 去抖（后一条取消前一条）
- **错在哪**：实测同桌帧间隔 **38~44% 在 250ms 以内**，两个座位几乎同时出决策时，
  前一个座位的帧被直接丢掉
- **现象**："第一个座位没提示，第二个才有"
- **修正**：去掉去抖，逐条处理
- **教训**：MQTT 是"每帧都是全量快照"，不是"增量补丁"。丢帧 = 丢状态

### 坑 4：决策表每帧重建，只装一个座位

- **做了什么**：`decisions = {}` 每个 playerSeat 帧重建一次
- **错在哪**：PP 服务器**一次只推一个座位**的帧 → 重建后就只有那个座位，
  另一手永远没有决策信息
- **现象**：多座位时只有一个有 EV
- **修正**：改成模块级 `decision_cache` 整局累积，`betsopen` 时才清空
- **教训**：**跨帧的状态必须累积，不能每帧重建**

### 坑 5：用 `activeHand is False` 判断"做完了"

- **做了什么**：`if hv.get("activeHand") is False and not hv.get("decisionTimer"): 熄灭`
- **错在哪**：服务器**大多数帧根本不带** `activeHand`（值是 `None`），
  `None is False` → `False`，条件永不成立
- **现象**："决策提示一直有在，直到这一局结束下一局开始才清空"
- **修正**：换成顺序轮流判定 `_now_turn()`
- **教训**：**判断字段存在性之前，先实测这个字段到底出不出**（这次就是没实测）

### 坑 6：用"别人开始决策"当熄灭信号

- **做了什么**：`_now_turn()` 返回本帧带 offer 的手，**其余所有亮着的手全部熄灭**
- **错在哪**：单座位时看起来正常。但同一个玩家坐多个座位时：
  - 7 号亮 → 1 号被灭
  - 1 号亮 → 7 号被灭
  - → **永远只剩一个亮**
- **现象**："同一个玩家坐三个座位，为什么就只有一个有决策提示"
- **修正**：熄灭范围限制在**本帧这个座位**（`k.split("_")[0] == mapped_seat`）
- **教训**：**每个座位的帧只能管自己这个座位。** 跨座位影响一律是错的

### 坑 7：用 `currentDecision` 判断"玩家已提交"

- **做了什么**：`if hv.get("currentDecision"): 熄灭`
- **错在哪**：`currentDecision` 在**决策还开着的时候就已经带值**，
  不是"按下按钮才出现" → 一收到帧就灭
- **现象**："你不改没事，现在改了连决策提示都没了"
- **修正**：整段回退，删掉
- **教训**：同上，字段语义不确定就别用来做开关

### 坑 8：用牌面指纹 `_handSig` 猜"这一手过去了"

- **做了什么**：`同一手牌 + cashOut 报价消失 → 判定已提交，删 canDecide`
- **错在哪**：又是在"推断"。服务器把 `cashOut` 撤掉的原因有很多种，
  不只是玩家提交 → 仍然误杀
- **现象**：提示仍然不对
- **修正**：整段删除
- **教训**：**这里是第 4 次用"推断"替代"事实"了。** 见下节铁律

## 三、铁律（以后照这个来，别再发明）

### 铁律 1：只跟 `decisionOffer`

```python
do = hv.get("decisionOffer")
if isinstance(do, dict):
    st["canDecide"] = True                     # 有 offer → 亮
    if do.get("cashOut") is not None:
        st["cashOut"] = do["cashOut"]
else:
    st.pop("canDecide", None)                  # 没 offer → 灭
    st.pop("cashOut", None)
```

就这六行。**不要再往里加 `or` 条件，不要再加别的字段。**

### 铁律 2：每个座位的帧只管自己

```python
flat_key = f"{mapped_seat}_{hk}"     # 只处理本帧这个座位
```

**永远不要**写出 `for k in _dc: if k not in turn: 熄灭` 这种跨座位逻辑。

### 铁律 3：不确定的字段，先实测再说

```bash
# 实测某个字段到底出不出
python - <<'EOF'
import json, asyncio, websockets, collections
# 连 ws://pp.knewb2u.com:8888/ws，订阅 pp/table/#，统计字段出现次数
EOF
```

**不要靠猜、不要靠推断、不要靠"服务器应该会……"。** 这次栽了四次，全是这个原因。

### 铁律 4：改完必须重启两个进程

`PPBJ.py` 和 `pp_receiver_vps.py` 都是长驻进程。只改文件不重启 = 改了等于没改。

### 铁律 5：git 只用 checkout 单文件，不用 revert / add -A

```bash
# ✅ 回退单个文件
git checkout <commit> -- "PP主程序/PPBJ.py"

# ❌ 绝对不要
git revert <commit>      # 会把当时 add -A 顺带进来的文件一起删掉
git add -A              # 会把不相干文件一起提交，回退时一起炸
```

> **真实事故**：2026-10-20 用 `git revert` 回退，把 `PP主程序/` 下
> `config.ini` / `login_198198.py` / `table_id.txt` / `WSS.py` / `restart_chain.py` 等
> 十几个文件一起删了。后来从 `40f5054` 那个 commit 里 `git checkout` 才全救回来。
> **这个项目文件不全是 git 管理的，revert 极其危险。**

### 铁律 6：`PPBJ.py` 带 UTF-8 BOM

```python
# ✅ 读写都用 utf-8-sig
s = open("PPBJ.py", encoding="utf-8-sig").read()

# ❌ 用 utf-8 读会报 SyntaxError: invalid non-printable character U+FEFF
```

写回时如果要保持 BOM：

```python
raw = open(p, "rb").read()
bom = raw.startswith(b"\xef\xbb\xbf")
out = s.encode("utf-8")
if bom: out = b"\xef\xbb\xbf" + out
open(p, "wb").write(out)
```

## 四、最终正确实现（当前代码，`0b300d9`）

### `PPBJ.py` — `listen_ws()` 里 playerSeat 分支

```python
raw_seat = ps_data.get("seatNumber")
if raw_seat is not None:
    mapped_seat = "0" if raw_seat == -1 else str(raw_seat + 1)
    _dc = decision_cache.setdefault(table_name, {})
    for hk, hv in ps_data.items():
        if not (hk.startswith("h") and isinstance(hv, dict)):
            continue
        flat_key = f"{mapped_seat}_{hk}"
        do = hv.get("decisionOffer")
        if isinstance(do, dict):
            st = _dc.setdefault(flat_key, {})
            st["canDecide"] = True
            if do.get("cashOut") is not None:
                st["cashOut"] = do["cashOut"]
        else:
            st = _dc.get(flat_key)
            if isinstance(st, dict):
                st.pop("canDecide", None)
                st.pop("cashOut", None)
    decisions = _dc
```

外加 `betsopen` 分支清空整局缓存：

```python
elif "betsopen" in data:
    clear_decision_cache(table_name)
```

### `pp_receiver_vps.py` — EV 触发

```javascript
const _hasCo = (h.cashOut !== undefined && h.cashOut !== null)
const _live = !!h.canDecide              // ← 单一条件，cashOut 只当参数传
```

其余：缓存 key 带 `cashOut` + `betAmount`；无 250ms 去抖；`dataset.shown` 防重复 fetch。
