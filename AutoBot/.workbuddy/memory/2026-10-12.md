## 15:58 【关键代码发现】「被踢」不走 STOP_ON_DISCONNECT，且踢人判断没比座位号

用户追问：明明约好断线就停，为什么截图里被踢后又跑去重连？

**原因 1：被踢是「正常 return」，不是异常，STOP_ON_DISCONNECT 管不到。**
- `main.py:1256-1264`：`stand/timeout` 分支 → `log("[⛔] Kicked from seat by server … re-rolling")` → `return`（返回 None）。
- `main()`（main.py:1468-1483）：`stopped_reason` 只在 `except ConnectionClosed` / `except Exception` 里赋值；
  `reason=None` → `if reason:` 不成立 → `stop_reason` 空 → 跳过停止分支 → `sleep(2)` → 回到 while 顶部 **重连**。
- 即：`STOP_ON_DISCONNECT` 只覆盖「网络断/异常」，覆盖不到任何「正常返回」的出口。
- `listen_table` 内正常返回/主动断开的口子（会静默重连）：
  `939, 969, 976-977(无空位 ws.close), 988, 993, 1004, 1027, 1031, 1040, 1046, 1062, 1264, 1289`，

**原因 2：踢人判断只比 user_id，没比座位号 → 旧座位的残留事件会把当前连接一起拆掉。**

  user_id 是我们自己的，与座位号无关，所以代码**根本区分不了**"踢的是旧座位还是当前座位"。
