# PP AutoBot 多客户端余额看板 · 部署与运维说明书

> 目的：多台 VPS 上各跑一份 AutoBot，老板打开一个网页就能看到**每台的余额、在跑哪张桌、状态、最后更新时间**。
> 最后更新：2026-10-13

> **每台 VPS 什么都不用配。** 看板上的名字就是这台机的**来源 IP** —— 服务端按上报请求的源地址自动认得。
> exe 丢上去双击就跑，不用改任何配置文件。
> （万一取不到真实来源 IP —— 反代 / 内网 —— 会自动退回按「机器指纹」发号 VPS-1 / VPS-2 …）

## 二、中心服务端（只需部署一次）

### 2.1 文件

`balance_board.py` —— **零依赖**，只用 Python 标准库（无需 pip 安装任何东西）。

### 2.2 启动

```bash
# 上传后，在服务器上执行（默认端口 8899）
nohup python3 balance_board.py > board.log 2>&1 &

# 换端口（一般不用）
python3 balance_board.py 8899
```

查看日志 / 确认存活：

```bash
tail -f board.log
# 正常输出示例：
# [board] 看板已启动 → http://0.0.0.0:8899/   (状态文件 /root/balance_state.json)
# [board] 上报端点 POST /report   token 160b92…5928
```

### 2.3 端口放行（关键，漏了就打不开）

两层都要开：

**① 云服务商安全组 / 防火墙面板**（控制台里操作）

| 协议 | 端口 | 来源 | 动作 |
|---|---|---|---|
| TCP | `8899` | `0.0.0.0/0` | 允许 |

**② 服务器本身的防火墙**

```bash
# CentOS / Alma / Rocky（firewalld）
sudo firewall-cmd --permanent --add-port=8899/tcp && sudo firewall-cmd --reload

# Ubuntu / Debian（ufw）
sudo ufw allow 8899/tcp

# Windows 服务器（管理员 PowerShell）
New-NetFirewallRule -DisplayName "BalanceBoard 8899" -Direction Inbound -Protocol TCP -LocalPort 8899 -Action Allow

# 纯 iptables
sudo iptables -I INPUT -p tcp --dport 8899 -j ACCEPT
```

### 2.4 让服务开机自启（可选，建议）

```bash
sudo tee /etc/systemd/system/balanceboard.service > /dev/null <<'EOF'
[Unit]
Description=PP AutoBot Balance Board
After=network.target

[Service]
Type=simple
WorkingDirectory=/root
ExecStart=/usr/bin/python3 /root/balance_board.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now balanceboard
sudo systemctl status balanceboard
```

### 2.5 接口一览

| 方法 | 路径 | 用途 |
|---|---|---|
| `POST` | `/report` | 客户端上报（必须带 token） |
| `GET` | `/api/clients` | 看板数据（JSON，页面每 3 秒拉一次） |
| `GET` | `/` | 网页看板 |
| `GET` | `/health` | 存活探针 |

### 2.6 服务端配置项（`balance_board.py` 顶部）

| 变量 | 默认 | 说明 |
|---|---|---|
| `TOKEN` | `160b928a…5928` | 上报密钥，**必须与客户端一致**；不对一律 403 |
| `PORT` | `8899` | 监听端口 |
| `OFFLINE_AFTER` | `60` | 超过这么多秒没上报 → 该行整行标红 |
| `HEARTBEAT_HINT` | `30` | 客户端心跳间隔（仅页面提示） |
| `SHOW_PNL` | `False` | 「今日盈亏」开关，默认关闭（原因见 [§6](#六已知限制)） |
| `TZ` | UTC+8 | 按马来西亚时间分「天」 |

改完**重启服务**生效：

```bash
pkill -f balance_board.py && nohup python3 balance_board.py > board.log 2>&1 &
```

## 三、客户端（每台 VPS）

### 3.1 文件

| 文件 | 说明 |
|---|---|
| `dist/PP_AutoBot.exe` | 主程序（已内置上报功能，**已含配置，直接跑**） |
| `bot_config.ini` | **可选**。只有想覆盖默认值（比如给某台机固定一个名字）才需要放 |

### 3.2 配置

**默认什么都不用建。** `report_url` / `report_token` 已经打包在 exe 里；看板上的名字由服务端按**来源 IP** 自动认得。
每台 VPS 直接把 exe 双击起来就行。

只有在需要「手动指定名字」时，才在 exe **同一个文件夹**建 `bot_config.ini`：

```ini
[bot]
username = KnewB178
password = Aaaa7788!
base_url = https://www.198198.io
feed_url = ws://pp.knewb2u.com:8888/ws

; ── 余额上报 ──
; client_id 一般不填 —— 看板上的名字由服务端按来源 IP 自动认得
; 想给这台机固定手写一个名字（不显示 IP），才取消下面这行的注释（旧行为，可回滚）
; client_id = VPS-1
report_url = http://pp.knewb2u.com:8899/report
report_token = 160b928a4caa227b44aab5fa7adc5928
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `client_id` | ❌ **可不填** | 不填 → 看板用**来源 IP** 当名字（推荐）。填了 → 就用你写的名字，**手填优先** |
| `report_url` | ✅（已在 exe 内） | 中心看板的上报地址，固定 `http://pp.knewb2u.com:8899/report` |
| `report_token` | ✅（已在 exe 内） | 与服务端 `TOKEN` 完全一致 |

> **只有 `report_url` 或 `report_token` 留空才等于停用上报**；`client_id` 空着没有任何影响。

> **为什么配置要放 exe 旁边？** 打包后程序会优先读 **exe 同目录**的 `bot_config.ini`；读不到就用打包进去的那份。所以覆盖配置**不用重新打包**。

### 3.3 运行 & 怎么确认它在报

双击 `PP_AutoBot.exe` → 粘贴 wss URL。

⚠️ **客户端启动时不会打印上报状态**（代码里没有那行输出）。想确认它在不在报，用下面任一种：

| 方法 | 怎么看 |
|---|---|
| 看板页面 | 打开 `http://pp.knewb2u.com:8899/`，多出一行新的（名字是那台的 IP）就是它在报（约 3～5 秒内出现） |
| 看板接口 | `curl -s http://pp.knewb2u.com:8899/api/clients` 看有没有新 `client_id` |
| 服务端日志 | 服务器上 `tail -f /root/board.log`，每笔上报会打 `[board] 1.2.3.4: 余额 …`（走回退发号时才打 `[board] 新机器 M-XXXX → VPS-1`） |

> 上报是**静默失败**的（故意如此，为了不拖慢下注），所以客户端那边不会报错 —— 只能按上表从服务端看。

### 3.4 名字是怎么定下来的

服务端认的是**上报请求的来源 IP**，所以看板上每一行就是那台机的 IP。

| 情况 | 看板上显示 |
|---|---|
| 没填 `client_id`（默认） | 那台机的**来源 IP**（如 `203.0.113.7`） |
| 同一台机器重启/重开 | 还是那个 IP（只要 IP 没变） |
| 填了 `client_id` | 就用你写的名字（**手填优先**，此时不显示 IP） |
| 那台机**换了 IP**（换机房 / 重拨） | 会变成**新的一行**，旧 IP 那行留「掉线」 |
| 取不到真实 IP（反代 / 内网 / 本机） | ⚠ 自动退回按「机器指纹」发号 `VPS-1 / VPS-2 …`（避免一堆机器都叫 `127.0.0.1` 撞名） |

> 想改回「不看 IP，一律发号 VPS-N」：把 `balance_board.py` 顶部的 `NAME_MODE` 改成 `"seq"`，重启服务即可。

### 3.5 上报规则

| 时机 | 行为 |
|---|---|
| 粘 URL 后 | 约 3～5 秒内发出第一笔（余额本来就每 3 秒轮询一次，直接复用） |
| 余额变化 | **立即**上报 |
| 余额没变 | 每 **30 秒**心跳一次（让老板端能区分「没变化」和「掉线」） |
| 程序停止 | 补报一次 `status=stopped` + 停止原因 |
| 发送方式 | 后台线程、超时 3 秒、**失败静默不重试** → 绝不拖慢下注 |

### 3.6 客户端开关（`main.py` 顶部）

| 变量 | 默认 | 说明 |
|---|---|---|
| `REPORT_ENABLED` | `True` | 总开关。`False` = 完全不发任何上报请求 |
| `REPORT_HEARTBEAT` | `30` | 心跳间隔（秒） |
| `REPORT_TIMEOUT` | `3` | 单次上报超时（秒） |

## 四、老板端

浏览器打开 **`http://pp.knewb2u.com:8899/`** 即可。

- **不用装东西、不用登录、不用手动刷新** —— 页面自己每 3 秒更新一次
- 手机浏览器也能开（自适应）

界面示例（顶部两张卡片 + 表格）：

```
余额合计（仅在线）                   在线客户端
7,083.75 MYR                        2 / 2
147,297,000.00 IDR
```

| 客户端 | 余额 | 币种 | 当前桌 | 状态 | 最后更新 |
|---|---|---|---|---|---|
| 203.0.113.7 | 7,083.75 | MYR | Blackjack 25 | 运行中 | 2 秒前 |
| 45.32.100.9 | 147,297,000.00 | IDR | Blackjack 9 | 运行中 | 8 秒前 |

> 客户端名字 = 那台机的**来源 IP**；「余额合计」**按币种分开统计**（MYR 与 IDR 不相加），每个币种一行。
| VPS-3 | 3,120.75 | MYR | — | 已停止 | 5 分钟前 ⚠ |

- 顶部两块卡片：**在线客户端数**、**余额合计（仅在线）**
- **超过 60 秒没上报 → 整行标红**，一眼看出哪台挂了
- 若某台程序已停止，状态显示「已停止」（超过 60 秒后会转为红色「掉线」）

## 五、常见问题排查

| 现象 | 原因 / 处理 |
|---|---|
| 网页打不开 | ① 服务没跑：`ss -lntp \| grep 8899`；② 端口没放行：云安全组 **和** 防火墙两层都要开 |
| 网页能开，但没有数据 | 客户端没上报。**客户端不会报错**（静默失败），只能从服务端查：`tail -f board.log` 有没有那台的 IP 上报记录 |
| 有上报记录但还是没数据 | token 不一致（服务端 `TOKEN` vs 客户端 `report_token`）；`board.log` 里会有 `拒绝：token 不符` |
| 看板出现两条同一台机的记录 | 那台机**换了 IP**（或走了回退发号）→ 被当成新的一行。旧行会自己变「掉线」，忽略即可；想固定就用 `client_id` 手写名字 |
| 多台机只显示一台 | 名字撞了：要么两边手填了同一个 `client_id`，要么都走了回退发号且机器指纹相同。用默认（都不填 + 各自独立公网 IP）不会撞 |
| 名字是 `VPS-1 / VPS-2` 而不是 IP | 服务端拿不到真实来源 IP（反代 / 内网），走了**回退发号** —— 属正常兜底；也可能是 `NAME_MODE` 被改成了 `"seq"` |
| 显示「掉线」 | 那台超过 60 秒没上报（程序关了 / 网络断了 / 机器挂了） |
| 重启服务器后看板空了 | 数据在 `balance_state.json`，除非文件被删；没装 systemd 的话服务本身也需要重新起 |

查看服务端日志里的拒绝记录：

```bash
grep "拒绝" board.log
```

## 六、已知限制

1. **「今日盈亏」默认关闭**。原因是它只能以「当天第一次收到上报时的余额」为起点，**充值 / 提现会被算成盈亏**，数字不可信，因此不显示。
   - 底层仍照常记录 `open` / `pnl`，如需恢复：把服务端 `SHOW_PNL` 改成 `True` 并重启，历史数据直接可用。
2. **只统计主余额**，不含红利余额（`bonusBalance`）。
3. **数据落盘在服务端**（`balance_state.json`），服务重启不丢；但**删掉该文件就等于清空历史**。
4. **看板页面本身没有密码**，任何人只要知道网址就能看（只能看，不能改）。
   - 上报接口有 token 保护，别人**无法伪造数据**。
   - 若需给页面加密码，可在 `balance_board.py` 里加 HTTP Basic Auth。
5. **上报是静默失败的**（为了不拖慢下注）。所以出问题时不要指望客户端报错，按 [§5](#五常见问题排查) 的顺序查。
6. **默认按来源 IP 命名**：那台机 IP 一变，看板上就会出现新的一行、旧行变「掉线」。要绝对稳定的名字就直接手填 `client_id`。
7. **回退机制**：取不到真实来源 IP（本地回环 / 内网 / 反代）时，自动退回按「机器指纹」发号 `VPS-1 / VPS-2 …`
   （按首次上报先后，号固定不回收）。**删掉服务端的 `balance_state.json` 会连指纹映射一起丢**，
   回退号会从 `VPS-1` 重新开始。机器指纹 = 主机名 + 网卡 MAC 的哈希 —— 同一台机重启 / 换目录不变，
   但**换网卡、重装系统会变**。

## 七、日常运维速查

```bash
# 看服务在不在
ss -lntp | grep 8899

# 看实时日志
tail -f /root/board.log

# 从外部验通（换台机器跑）

```

## 八、涉及文件清单

| 文件 | 位置 | 作用 |
|---|---|---|
| `balance_board.py` | 服务器 `/root/` | 中心看板服务（零依赖）。**含命名逻辑（默认按来源 IP，`NAME_MODE` 可切），改动后必须重新上传重启** |
| `balance_state.json` | 服务器 `/root/`（自动生成） | 各客户端最新状态 **+ 回退发号用的机器指纹→VPS-N 映射**（重启不丢；删掉=回退号重来） |
| `board.log` | 服务器 `/root/`（自动生成） | 服务日志（含每笔 `IP: 余额 …`、回退时 `新机器 … → VPS-N`、`拒绝：token 不符`） |
| `dist/PP_AutoBot.exe` | 各客户端 VPS | 主程序（已含上报配置，直接双击跑） |
| `bot_config.ini` | 各客户端 VPS，**exe 同目录**（可选） | 只在要覆盖默认值 / 手写 `client_id` 时才需要 |
| `main.py` | 开发目录 | 主程序源码（`_machine_fingerprint()` 机器指纹、`REPORT_*` 开关、上报逻辑） |
| `build_release.py` | **项目根目录** | 一条命令：打包 exe → 自检 → 上传 GitHub Release。改了 `main.py` 后跑它 |
| `google_sheet_sync.gs` | 本项目（粘到 Google Apps Script） | 把看板数据定时同步到 Google 表格，见 `余额表同步说明.md` |
| `余额表同步说明.md` | 本项目 | Google 表格同步方案（方案 C：Google 定时来拉）的部署说明 |
