# PP AutoBot · 余额同步到 Google 表格（方案 C）

> 目的：老板不用开看板网页，直接在 Google 表格里就能看到每台 VPS 的余额、在跑哪张桌、活没活。
> 最后更新：2026-10-13

---

## 一、这套是怎么跑的

```
 各台 VPS ──上报──▶ 看板服务 (pp.knewb2u.com:8899)
                          │
                          │  /api/clients   ← 一次返回所有机器
                          ▼
                   Google 定时来拉（每分钟）
                          │
                          ▼
                  表格新增两页：pp_live / pp_summary
```

**关键点：Google 是「自己去拉」，不是「等别人推」。**

| | |
|---|---|
| 机器人 / exe / 看板 | **一个字都不用改**，exe 也不用重新打包 |
| 拉取次数 | 只跟「多久拉一次」有关，**跟 VPS 台数无关**：2 台 1 次/分钟，30 台还是 1 次/分钟 |
| Google 挂了 / 配额爆了 | 只影响这两页，机器人照跑、看板照开 |

### ⚠ 和你原来的 `doPost` 是两条互不干扰的线

| | 谁在用 | 写哪一页 | 怎么写的 |
|---|---|---|---|
| **你原来的 `doPost`** | 别的平台（正在用，**不要动**） | `live` | 按名字找行 → 改余额 / 追加行 |
| **本方案（新加的）** | PP AutoBot | `pp_live` / `pp_summary`（**新建的**） | 每页整页覆盖 |

**本方案刻意不碰 `live` 页。** 原因是本脚本是「整页清空再写」的刷新方式 —— 如果写进 `live`，会把别的平台辛苦记下来的行**全部清掉**。所以另开两页，各写各的，互不影响。

（同一个 Apps Script 项目里，各脚本文件的变量和函数是**共享**的，所以本脚本所有变量都带 `PP_` 前缀、函数都带 `pp` 前缀，不会和你原来的代码撞名。）

## 二、前提

看板服务已经部署并**重启过** —— 也就是说 `http://pp.knewb2u.com:8899/api/clients` 能打开。

浏览器直接访问这个地址，应该看到一大段 JSON（里面有 `clients`、`totals`）。看不到就先别装，回头查服务端。

## 三、安装（只做一次，约 5 分钟）

| 步 | 操作 |
|---|---|
| 1 | 打开 Google 表格 → 菜单 **扩展程序 → Apps Script** |
| 2 | 左侧「文件」旁边的 **＋ → 脚本** → 命名 `sheet_sync`。<br>★ **是新建一个文件**；你原来的 `Code.gs`（`doPost`）**一个字都不用动、不要删** |
| 3 | 把 `AutoBot/google_sheet_sync.gs` 的全部内容粘进这个新文件 → 保存 |
| 4 | 点「运行」→ 选 **`ppPullBalance`** → 首次跳授权，一路同意。跑完表格里会多出 `pp_live` / `pp_summary` 两页 |
| 5 | 再点「运行」→ 选 **`ppInstallTrigger`** → 之后每分钟自动拉 |

> 第 4 步报「找不到函数」是没保存；报「需要授权」点是即可。
>
> 想确认定时器装上了：左侧「触发器」（闹钟图标）应看到一条 `ppPullBalance` 的“时间驱动 · 每分钟”。

**日常操作**

| 想干嘛 | 运行哪个 |
|---|---|
| 手动刷一次 | `ppPullBalance` |
| 暂停同步 | `ppRemoveTrigger` |
| 重新开始 | `ppInstallTrigger`（会先删旧的再装） |

暂停只是这两页不更新了，**看板、机器人、`doPost` 那条线完全不受影响**。

## 四、表格长什么样

### `pp_live` 页 —— 每台机一行

| 名称 | 余额 | 币种 | 当前桌 | 状态 | 最后更新 | 距今 | 在线 | 备注 |
|---|---|---|---|---|---|---|---|---|
| 203.0.113.7 | 7,083.75 | MYR | Speed Blackjack 9 | 运行中 | 12:43:38 | 3 秒前 | 在线 | |
| 198.51.100.5 | 1,234.50 | MYR | | 已停止 | 12:41:38 | 2 分钟前 | 掉线 | 空座位 5 秒超时 |

- **名称** = 那台机的**来源 IP**（跟看板一致）。想让某台固定显示成 `VPS-1` 这种名字，就在它的 `bot_config.ini` 里手填 `client_id`
- **距今 / 在线** = 服务端算好的，超过 60 秒没上报就是「掉线」

### `pp_summary` 页 —— 按币种合计

| 币种 | 余额合计 | 在线台数 |
|---|---|---|
| IDR | 147,297,000.00 | 1 |
| MYR | 7,083.75 | 1 |

下面还带：在线/总数、本表拉取时间、看板时间、心跳与掉线判定、数据源地址。

> **MYR 和 IDR 是分开算的**，不会像以前那样混加成一个数。
> 如果看板那边 `SHOW_PNL` 打开了，这里会多一列「今日盈亏合计」。

## 五、配额（为什么改成 1 分钟也安全）

免费 Gmail 账号的 Apps Script 配额：

| 限制 | 免费账号 |
|---|---|
| 每天脚本总运行时间 | 90 分钟 |
| 每天 URL Fetch 调用 | 20,000 次 |

本方案实际用量：

```
每天 1,440 次拉取 × 每次约 2 秒 ≈ 48 分钟/天   → 在 90 分钟以内 ✅
```

**台数从 2 台涨到 30 台，这个数字几乎不变** —— 因为一次拉取就把所有机器都取回来了。

想更省就把 `google_sheet_sync.gs` 顶部的 `PP_EVERY_MIN` 改成 `5`（变成约 10 分钟/天），代价是表格最多晚 5 分钟。

> ⚠️ **一个 Google 的硬限制**：定时器只支持 **1 / 5 / 10 / 15 / 30** 分钟这五档，写「2 分钟」是不允许的。
> （我之前跟你说的「每 2 分钟」做不到，抱歉 —— 所以这里默认用 **1 分钟**，用量仍在配额内。）

## 六、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 表格完全不动 | 触发器没装：运行 `ppInstallTrigger`；或看 Apps Script 左侧「执行记录」里的报错 |
| 报 `拉取失败 HTTP xxx` | 看板服务没起，或 `8899` 端口被防火墙/安全组挡了（先浏览器访问那个接口试试） |
| 报 `返回的不是 JSON` | 中间被什么拦了（运营商/公司网络首页之类），返回内容是 HTML |
| 表格里少了几台机 | 那些机没在报。看 `pp_live` 页里它们是不是显示「掉线」 |
| 名字不是 IP | 那台机在 `bot_config.ini` 里手填了 `client_id`（手填优先，正常） |
| 时间差 8 小时 | 不会 —— 脚本已写死 `Asia/Kuala_Lumpur`。真差了就是有人改了 `PP_TZ` |
| **`live` 页的数据会不会被弄丢？** | **不会。** 本方案只写 `pp_live` / `pp_summary` 两页，从不碰 `live` |
| 想连历史一起留档 | 现在 `pp_live` 页是**每次覆盖**（镜像当前状态）。要做流水账得另加逻辑，见下 |

## 七、边界（先说清楚）

1. **不是秒级**，最多晚 1 分钟（Google 定时器的最小间隔就是 1 分钟）。
   > 真要秒级就得改成「服务端转发」——那要动 `balance_board.py`，还会让 Google 的慢拖累看板，目前不值得。
2. **只镜像当前状态**，不存历史。真要做流水账：30 台 × 每分钟一行 = 4.3 万行/天，一个月就 130 万行 —— 得改成「只在余额变化时记一行」或按月分表，否则表会爆。
3. **`doPost` 继续保留、继续用**。本方案和它完全分开（不同页、不同变量名），互不影响。
4. 表格 ID 写死在脚本顶部（`PP_SHEET_ID`）。要同步到别的表就改那一行。
5. 两页的名字也可以在顶部改：`PP_SHEET_MAIN` / `PP_SHEET_SUM`。
